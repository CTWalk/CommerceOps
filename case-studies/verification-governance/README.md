# Verification governance

Verification is not complete merely because enough green runs have accumulated.

CommerceOps uses an evidence-based stopping rule:

1. classify the failure owner;
2. repair the owning layer;
3. re-enter the affected gate or suite;
4. repeat only when repetition can falsify a live uncertainty or an explicit acceptance contract requires it.

A deterministic, root-caused harness defect that is structurally removed does not automatically justify identical full-gate reruns solely to increase the green count. Conversely, unresolved, stochastic, intermittent, or environment-qualification risks may require repetition.

This keeps acceptance tied to uncertainty and evidence rather than ceremony.
